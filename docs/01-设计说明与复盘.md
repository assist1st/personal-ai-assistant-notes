# 设计说明与迭代复盘（W1）

> 配套 `README.md`。本文只讲**方法、决策与边界**，不含任何真实记忆内容、规则全文、客户端配置或凭据。

---

## 1. 三层的定义与边界

| 层 | 存什么 | 变更频率 | 作用域 | 写错层的典型后果 |
|---|---|---|---|---|
| 云端画像 | 稳定规则、协作方式与长期偏好**框架** | 极低 | 跨项目通用 | 把临时状态写成永久规则，之后所有项目都被带偏 |
| 用户级 | 已确认的事实、约定、口径 | 低 | 跨项目、按主题归档 | 同一事实多处留存，改一处漏其余 |
| 工作区级 | 当前项目状态、待办、决策记录 | 高 | 仅当前项目 | 项目结束后状态残留，被误调取到别的项目 |

**硬约束**：同一事实只存一处；层级之间不互相兜底（低层找不到不向高层"猜"）；状态类内容随项目启停归档，不长期驻留。

---

## 2. 两条主流程

**写入流程**：新增信息 → 归类（规则 / 事实 / 状态）→ 去重（是否已有同义条目）→ 归属层 → 冲突裁决 → 落笔 → 更新速查文档索引。
归类不通过的信息**不落笔**，宁可留在待归类区，也不污染正式层。

**调取流程**：提问 / 新任务 → 判断命中哪几层 → 只取命中层 → 生成方产出 → 校验方核对"结论是否有对应条目、层级是否取对" → 通过才输出 → 回写状态。
不做整库读取：单次调取控制在最小必要范围内，既是效率考虑，也是减少噪声把答案带偏。

## 3. 13 条治理规则的类别（不公开全文）

规则按作用分成八类，合计 13 条；**只列类别，不列具体条文**（条文可能含个人信息与真实项目细节）：

1. **准入类**：什么可以写入、什么必须留在待归类区
2. **分类类**：规则 / 事实 / 状态的判定顺序与歧义处理
3. **唯一性类**：同一事实只存一处、重复条目的合并方式
4. **冲突裁决类**：新旧冲突、跨层冲突时的优先级
5. **调取触发类**：什么条件下取哪一层、单次调取的上限
6. **摘要与版本类**：摘要只能从原始条目重生成、版本如何标注
7. **归档类**：项目结束后状态如何归档、何时清理
8. **隐私与边界类**：哪些内容一律不写入、哪些内容一律不对外

> 一条稳定经验：**规则本身也要受规则管**。新增规则必须先给归类建议、并说明它解决的是哪个真实冲突；否则规则会随例外无限膨胀。

## 4. 六版迭代顺序与动机（不写具体日期，按真实顺序）

| 版本 | 当时暴露的问题 | 这一版改了什么 |
|---|---|---|
| v1 | 所有信息堆在一个文档，找不到也改不干净 | 按时间归档 + 全文检索 |
| v2 | 同一事实多处出现，改动不同步 | 引入"同一事实只存一处"与去重 |
| v3 | 项目状态与长期规则混在一起，回答串味 | 拆成三层，明确作用域 |
| v4 | 例外太多，约定互相覆盖 | 把约定固化为治理规则并定冲突优先级 |
| v5 | 一个模型顺着上下文补出不存在的"事实" | 加双 AI 互审，校验方只做存在性核对 |
| v6 | 每轮摘要基于上一轮摘要，越压越偏 | 摘要改为从原始条目重生成；收紧触发条件 |

> 迭代顺序是真实的，**不标注、不伪造具体提交日期**。展示型仓库用「分章节提交 + 修订记录」体现演进即可。

## 6. 面试可能追问（照着 README 问，提前准备）

| 追问 | 回答要点 |
|---|---|
| 「13 条规则怎么来的，会不会太重？」 | 不是一次设计出来的，是从真实冲突里长出来的（举"同一事实多处留存""状态被当规则调取"两例）。每条都能对应一个具体问题；也正因为有"新增规则必须先归类"这条，才没膨胀。 |
| 「双 AI 互审会不会两个模型一起附和？」 | 关键是**校验方的任务被限定**：它不做开放式评价、不补内容，只核对"结论有没有对应已存条目、层级取对没有"，不一致就回退原文重取。用流程约束，而不是指望模型更聪明。 |
| 「这和 RAG / 知识库有什么区别？」 | 差别在**写入侧**：多数方案优化的是"怎么检索"，我主要解决的是"该不该存、存到哪、冲突了听谁的"。规模很小，靠规则和分层而不是向量召回；也正因如此，局限是没做检索评测。 |
| 「数字怎么验证？13 / 8 / 6 是凑的吗？」 | 规则和文档都是可数的实体，迭代 6 版各自对应上表一个具体动机。这些数字只用来说明规模，不夸大效果；如果面试官要看，能逐条讲清来历。 |
| 「为什么不把真实内容放出来，是不是没东西？」 | 真实内容是个人档案与对话记录，属隐私，公开的是**设计不是数据**。完整实现可现场演示或私有仓临时授权；这也正好说明我分得清"可展示"与"不该展示"。 |
| 「为什么不做成产品？」 | 单用户、无权限隔离、无量化评测、依赖客户端能力——给自己用够，给别人用会串数据。写进局限是刻意的，比包装成"可扩展系统"诚实。 |
